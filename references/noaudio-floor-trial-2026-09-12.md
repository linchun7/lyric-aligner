# 无音频成品下限实验：停止扩展，保留确定性修复

本轮结论：没有证据把现有 word / character ownership 重建升级为默认自动修复，也没有证据增加 Max 投入。保留一处共享排版函数的确定性修复，范围仅为已有词边界处的标点与横向空白顺序。正式生产冻结 tag 不移动；本地修复分支不等于新生产版本发布。

**真实回放**

五个历史批次共 3,286 cues。原始输入、canonical 顺序、BPM 配置和既有 Smart 输出绑定 SHA；隔离 Python 3.12 与仓库 requirements-dev 环境复跑，五批基线全部逐字节一致。历史批次是 development，不是 untouched holdout。已有 Best-Safe 成品作为英文批次的独立比较基线；未把其他批次的 Smart 副本称为新 Best-Safe。

| 对照 | 结果 | 判断 |
| --- | --- | --- |
| A0：现有 region word DP，原阈值 | 22 个区域，覆盖 51 cues，实际变化 47 cues | 19 个区域触发现有插词/Latin ownership 保护或与字符归属分配矛盾；不能自动放行 |
| A1：word partition 不可用时字符 fallback | 0 个触发区域 | 不足以判定字符路线有效或无效 |
| A2：同门槛下全部合格区域改用现有字符分配 | 7 个区域，14 个变化 cues | 仍有插删、重复和标点排版问题；不授予自动修改权限 |
| 最终排版修复 | 2 个 cues 的横向空白位置变化；其余相同 | 非横向空白字符、cue timing/topology、review 集合全部保持；仅支持排版修复结论 |

19 个触发保护的区域不是 19 个已被人工证实的错误；未触发保护也不等于正确。重复词可能来自真实重复演唱，canonical 整段一致不能决定 cue ownership。canonical 原文件自身还有粘词和疑似角色标记，不能用更多 DP 或降低阈值消除这些未知。

**最小修复与边界**

`text_repair._reflow_latin_horizontal_whitespace` 过去先删除横向空白，再把空格放到所有标点后面，因此可能破坏原有开引号或前缀撇号。现在仅在目标要求词边界、且已有槽同时包含标点和横向空白时，原位压缩横向空白。无标点的普通空格、需要新增或删除的词间空格、禁止拆词的换行，继续按原逻辑处理。

这是通用排版缺陷修复，没有新增模型、语言规则表、DP、selector、schema 或人工权威入口。先前会恢复冗余空白的较宽候选已被否决并保留失败证据。新增端到端回归用匿名合成文本复现开引号/撇号被挪动，并检查普通冗余空白仍被压缩。

**验证与停止规则**

- 没有独立原生人工响应，因此人工 Gold 为 0，blind PASS 为 false。已冻结 candidate-blind 待办与 unchanged controls，但其分区仍是 development；不能事后改为 untouched。
- 本轮没有重新执行 Max 重型音频链，也没有测出 Max 对完整成品的净胜率。暂停新增 Max 能力，保留已有复杂结构恢复能力。
- 不自动删重复词，不把整行 canonical 塞进半行 cue，不按语言降低阈值，不把 review 减少或测试通过当作质量收益。
- 若重新开启词义/归属路线，先获得新生产失败和独立原生人工真值，再冻结候选及 untouched 歌曲级集合。现有输出不能改标签复用为 holdout。

本地完整报告、输入 hashes、命令、私有对照、原生响应空模板与失败记录位于 `output/noaudio_floor_trial_20260912/`。原始生产输入和 final 默认保留；原始 source 快照、实验脚本与最终源码的等价验证一同保留。复跑旧基线须使用记录的旧代码提交或隔离快照，不得在已修改的 working tree 中绕过 source hash 校验。

## 2026-09-13 最小音频验证与正式收尾

**决定：关闭本轮无音频 lexical / ownership 重建开发，停止调 ownership/DP 阈值；保留已验证的排版修复。** 这是证据不足下的投入决定，不是“任何无音频修复都不可能”的理论结论。新的、可复现的确定性实现缺陷仍可维护；不再围绕这些旧样本扩展候选或降低门槛。Max 不增加新能力。

冻结的49组历史 development 案例覆盖176个标注槽位、175个不同的 dataset/cue，含25组 unchanged controls。每组依据已有任务的 final-mix 路径/哈希裁出上下文，合计582.365秒。复用现有 Faster-Whisper executor 和本机保留的 large-v3-turbo 权重，CPU int8，一次无提示解码；不给 Smart、canonical、候选或语言提示，不下载其他模型，不作文本引导重解码。

| 冻结对照 | 机器观察结果 | 允许的结论 |
| --- | --- | --- |
| A0：22个 word DP 候选区域 | 14个更接近 Smart，4个更接近候选，2个无观察，1个距离相同，1个仅展示差异 | 这里的“接近”是相对 ASR 的字符距离，不能当成14错/4对 |
| A2：7个 character 候选区域 | 4个更接近 Smart，2个更接近候选，1个仅展示差异 | 与A0共享案例/证据，不能合并成独立成功率 |
| cue ownership | 168/176槽位在“所有词完全落在原 cue 内”的诊断中有跨界、零时长或缺失观察 | 不代表168个真实归属错误；Whisper word times不能决定生产 boundary |
| 原生人工听审 | 响应0、Gold 0、human blind PASS=false | 最终成品正确率、人工修复量收益仍未知；不能宣称49组人工盲验完成 |

追加诊断复用既有 `_canonical_word_span`，不改门槛、不重解码。它在完整上下文中找到3个候选 cue 的唯一精确词序，其中只有1个属于单 cue 候选；该分析是在查看机器结果后设计，明确记为 exploratory，不能伪装成预注册验证。唯一的单 cue 候选保留为最优先人工确认项。其他区域存在总字符距离改善、内部某 cue 距离反而变差的情况；中文 unchanged control 也出现与既有字幕不符的疑似幻觉转写。高 token probability、整句词序吻合、区域净分改善都不足以授予自动修改 authority。

**局部音频的最小保留方向**：既有 Smart review → 现有 canonical 候选 → Pro 局部无提示 ASR → 人工确认单 cue 的明确词义修复。首个收益单位可以是一条已独立确认、相邻 cue 无退化的成品修复，不要求先重建整个 Max。若要宣称自动策略稳定优于 Smart，另需新歌曲级 untouched 集合上的逐 cue 净正确数、任何新增错误、词归属、timing/topology，以及实测人工编辑用时；旧49组不能重标 holdout。未有这些证据前，不实现新的自动 selector、不放宽词时长边界、不扩模型。

本轮新增物仅在本地 `output/blind_audio_trial_20260913/`：预注册、49段音频与原始机器响应、确定性比较、事后诊断、候选隐藏的人工听审页面及报告。没有新增生产源代码、schema、模型权重或 SRT 写回；人工阶段因缺独立原生响应仍待完成，其他实验和路线取舍已收尾。
